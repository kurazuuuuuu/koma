# ライセンス

3つの層に分かれる。混ぜると壊れる。

| 層 | 中身 | 選べるか | ライセンス |
|---|---|---|---|
| **リポジトリ** | ツール、スキル定義、定跡、設定雛形 | 選べる | **Apache-2.0**（[LICENSE](../LICENSE)） |
| **配布物** | Paper + プラグイン束 + datapack | **選べない** | **GPL-3.0**（Paper 由来） |
| **第三者プラグイン** | 個々の jar | 選べない | 個別 |

## なぜリポジトリに GPL 物を置かないか

Paper は GPL-3.0 で、Spigot → Bukkit → CraftBukkit から継承している。
Paper の jar、パッチ、GPL 由来の設定をコミットすると、**リポジトリ全体のライセンスが濁る**。

よって:

- 成果物は**インストール時に取得**する。コミットしない
- 配布物の組み立てはデプロイ時に行う。そこで GPL-3 の告知義務が発生する
- リポジトリには自前のコードと文書だけを置く

## 我々の法的位置

フォークせず、NMS を使わず、`paper-api` にリンクするのみ。
これは**すべてのプラグインと同じ立場**。

ただし正直に書くと:

> **GPL-3 の API にリンクするプラグインの法的地位は確定していない。**
> コミュニティ慣行として「プラグインは独立した著作物」として扱われているが、判例はない。

これは [`unknowns.md`](unknowns.md) の調査項目に入れてある。

## 配布するときの義務（GPL-3）

Paper を同梱して配るなら:

- 対応するソースの提供（または入手方法の明示）
- ライセンス文と著作権表示の同梱
- 改変した場合はその明示

koma は **Paper を改変しない**ので、上流の配布物をそのまま同梱し、告知を付けるだけで足りる。
フォークしないという決定が、ここでも効いている。

## 再配布できないプラグイン

**All Rights Reserved のプラグインを束ねて配ると違法**になる。
これは実際に多い（有料プラグイン、独自ライセンスのもの）。

したがってロックファイルは `license` と `redistributable` を持つ。

```json
{
  "id": "some-plugin",
  "version": "3.2.1",
  "sha256": "sha256:...",
  "license": "ARR",
  "redistributable": false
}
```

`koma install` は、`redistributable: false` の成果物を含む配布物を組み立てようとしたら**失敗する**。
自分用にインストールすることはできるが、配布物には入らない。

これは「真実を1つにする」と同じ話で、**ライセンスをメタデータではなく制約として扱う**。

## なぜ Apache-2.0 か

| 候補 | 判断 |
|---|---|
| **Apache-2.0** | ◎ 特許条項と商標条項がある。この規模なら MIT より安全 |
| MIT | ○ 単純。ただし特許条項がない |
| MPL-2.0 | ○ ファイル単位のコピーレフト。企業が取り込みやすい |
| AGPL-3.0 | △ セルフホスト前提だと効きが薄い。SaaS 化されたときだけ刺さる |

AGPL は「誰かが koma を商用サービス化して貢献ゼロ」を防ぎたいなら選ぶ。
現時点ではそこを気にしていないので Apache-2.0。

## 商標

Apache-2.0 は**商標を許諾しない**。フォークが `koma` を名乗るのは別問題として残る。
必要になったら `TRADEMARK.md` を置く。今は置かない（置くほどの状態ではない）。

## 文書

設計文書も Apache-2.0 に含める。CC-BY に分けるほどの量ではない。
分けると「どっちのライセンスか」を毎回確認することになり、コストに見合わない。
