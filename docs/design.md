# 設計

> Terraform の思想を、状態を持ち・順序に意味があり・実時間で動く系に適用し、エージェントが常時運用する前提に作り直したもの。

**この文書の状態**: 設計。実装なし。数値は断りがない限り `[未計測]` の見積もり。
計測したら条件とセットで置き換える。分かっていないことは [`unknowns.md`](unknowns.md) に置く。

## 確定事項

| 項目 | 決定 | 理由 |
|---|---|---|
| 土台 | **Paper** | エコシステムが可逆性（CoreProtect）と権限（LuckPerms）を無料で提供する |
| フォーク | **しない** | 追従コストが年 50–100 日と見積もられる `[未計測]`。マルチスレッド化の答えは Folia に既にある |
| Folia | **使わない** | 決定論が消える。検証コストが数倍 |
| NMS | **禁止**（静的検査で強制） | バージョン跨ぎで壊れる。コンパイラは検出しない |
| 世界状態の書き手 | **1本** | 50ms/tick の締切。分散に弱い |
| 決定論の適用範囲 | `(seed, version, generatorconfig, datapacks)` の内側のみ | バージョン跨ぎは契約外 |

## 層構成

```
[0] ディストリビューション   Paper（ピン）+ プラグイン束 + datapack + 設定（content-addressed）
[1] 薄いシム                 event → record → enqueue / apply。判断ロジックゼロ
[2] ポリシーエンジン         オフスレッド。不変テーブルを publish（変更時のみ）
[3] 状態                     MariaDB（プラグイン）/ Postgres（制御プレーン）
[4] reconciler               git（望ましい状態）→ plan / apply
[5] 検証                     純関数 / MockBukkit / GameTest / ボットE2E / 負荷
[6] 監査                     決定ログ（リプレイ可能）/ spark
[7] エージェント実行          Tier0 → Tier1 → 定跡(DAG) → ステートレスフリート
```

**[1] は薄く保つ。**ここに判断が入った瞬間、この設計は成立しない。

## 中核の判断

| 判断 | 内容 |
|---|---|
| **ポリシーは配布する、RPC しない** | ホットパスは原子参照と配列参照のみ。重い処理は変更時に逃がす |
| **認可カーネルは委譲する** | `decide(principal, action, resource, ctx)`。権限は LuckPerms、証跡は CoreProtect |
| **単一書き手 + 不変スナップショット** | tick スレッドは読み取りと適用だけを行う |
| **state file を持たない** | 実状態を毎回読む。真実を 2 つ作らない |
| **可逆性が自律性の上限** | 可逆 = 自動、不可逆 = 人間のゲート |
| **承認ではなく拒否権** | デフォルト実行。人間は異常だけ revert する |
| **推測させず、失敗させる** | 曖昧さは解決せずエラーにする |

### state file を持たない理由

Terraform が state を必要とするのは、クラウド API が全列挙を保証しないから。
Minecraft サーバーの状態は「ファイル + RCON + プラグインのレジストリ + ロックファイル」で**列挙できる**。

| Terraform | koma |
|---|---|
| `.terraform.lock.hcl` | `koma-lock.yaml`（対応する） |
| `terraform.tfstate` | **無い（意図的に）** |
| `terraform plan` | `koma plan` |
| `terraform refresh` | 不要（`describe` が常に新鮮） |

### 操作モデルは CRUD ではなくワークフロー

```text
プラグイン更新 = 監査 → plan → 適用 → カナリア → soak → 全台 → 検証
```

バケットはカナリアできないが、サーバーはできる。よって resource/provider（CRUD）ではなく
**skill + 定跡（DAG）** を単位にする。

### 失敗時は fix forward ではなく rollback

Terraform は戻さない（クラウド資源は戻せないことが多いので妥当）。
koma は**可逆性を設計に入れる**ので、戻せる。これが人間の承認を拒否権に置き換えられる理由。

### 反証条件

上の判断が間違っていたと分かる条件。ここが埋まらない決定は、決定ではなく願望。

| 判断 | これが観測されたら間違い |
|---|---|
| state file を持たない | 実状態の列挙が遅い、または不完全で、毎回読むと運用に耐えない |
| 世界状態の書き手は 1 本 | 単一スレッドの tick コストが 50ms に近づき、オフスレッド化だけでは足りない |
| シムは判断を持たない | オフスレッドの往復待ちが tick に現れる（平均ではなく p99 で） |
| 可逆性が自律性の上限 | 可逆な変更でも事故が起き、戻す判断自体に人間が要る |
| 定跡は静的 DAG | 静的 DAG で表せない作業が過半になる |
| フリートは会話しない | 成果物経由の受け渡しで情報が落ち、タスクが完了しない |

## サブシステム

### 成果物ストア（蔵）

- content-addressed。`store/v1/<sha[0:2]>/<sha[2:4]>/<sha>.jar` + `.meta.json`
- `koma-lock.yaml` に `provides`（コマンド・権限）と `shaded`（同梱ライブラリ）を持つ
- **ロールバック = ポインタ交換**（数 ms）→ 自律性の上限が上がる
- 取れないもの: 依存解決・隔離（Paper に概念が無い）
  → 代わりに**静的解析で衝突を検出して失敗させる**

### 監査（`koma audit`）

プラグインマネージャの差別化点。

- コマンド衝突 / 権限衝突 / 重複 shade / 欠落依存 / 幽霊依存
- shade されたライブラリの CVE（OSV / NVD）
- 能力差分（新権限、新通信先、新依存）
- **クラス索引**により `koma why <class>` が動く（jar 地獄のデバッグ）

### サプライチェーン

```text
①検出 → ②検証 → ③ピン → ④配布
```

- **ゲームサーバーはインターネットに出ない。**ストアが唯一の入口
- ハッシュは別経路から取得し、複数ソースの一致を要求する
- **ハッシュと署名では解けない領域がある**（作者アカウント乗っ取り、正当な更新への混入）
  → **バイトコード差分 + サンドボックス観測 + 段階配布**が実効的な統制
- 自動化しない条件: 新権限 / 新通信先 / 新依存 / exec・反射 / 配布チャネルが release 以外
- `review.status != approved` のものは導入不可

### 更新のゼロダウンタイム分類

| クラス | ダウンタイム | 手段 |
|---|---|---|
| 設定 / ポリシー / 権限 / datapack | **ゼロ** | 再読込 / publish-swap |
| ワールド | **ゼロ可** | blue/green |
| **自前プラグイン** | **ゼロ可** | シェル + 子クラスローダを最初から設計に入れる |
| **外部プラグイン** | ローリング | プロキシ + 複数台 |
| **単一共有ワールドの外部プラグイン** | **5–15 秒** `[未計測]` | 計画停止。ゼロは構造的に無理 |

スケジュール: 窓 + カナリア + soak + レート制限 + **自動ロールバック条件の事前定義**。更新はコアレスする。

### 形式

- **厳格 JSON**（ソート済み、4 段、500 行、`null` 禁止、整数のみ、ID は文字列、列挙は文字列、
  時刻は ISO-8601 UTC、ハッシュは自己記述、コメント禁止、`additionalProperties: false`、
  **重複キーはエラー**）
- 文書は JSON、ストリームは **JSONL**
- **`koma describe --json`** = 全体の真実が 1 ドキュメント。全値に来歴
- **`koma apply --expect-rev`** = 古い前提を拒否する（TOCTOU を潰す）
- クエリは `jq`（読み取り専用。書き戻し禁止）

### スキル

- 成果物として版管理する（プラグインと同じサプライチェーン）
- frontmatter: `schema_version` / `reversibility` / `tools`（**能力はスキルではなくポリシーから**）/
  `stop_on` / `max_iterations`
- **全ステップに verify コマンド**。無いならそれは手順ではなく文章
- 「適切に」「必要なら」は禁止。エージェントが推測で埋める
- **CLI に対して型検査する**（`koma skills verify`）+ スキル・エバル
- ログ・チャット・jar 内文字列は**データであって指示ではない**

### ルーターとフリート

- **Tier0（Jev）**: 毎イベントのトリアージ。tick 経路に入れない
- **Tier1（Haiku）**: 定跡の選択 + パラメータ抽出。**閉集合**で、`unknown` が第一級
- **分解は静的 DAG**。実行時に LLM に分解させない
- `unknown` → 定跡の執筆ループ（これが成熟度の指標になる）
- **フリートはチャットではなくビルドグラフ**: ステートレスなワーカー + 成果物経由の受け渡し。
  会話履歴を渡さない
- ディスパッチャ: タスクリース / **資源リース** / 冪等キー / blast radius 上限 / 予算 / DLQ
- モデルは**ピン留めされた成果物**。上流のモデル更新はサプライチェーン事象として扱う

### 脳

- **事実**（不変・権威）= 蔵 + 棋譜
- **信念**（導出・版付き・参照専用）= 統合ジョブだけが書く
- 再構築可能でなければならない。**脳は真実ではない**（食い違ったら蔵が勝つ）
- 最も価値があるのは**人間の拒否履歴** → 方針に昇格する
- **`koma brain diff` が週次監査の面**

### 盤

- 棋譜 → **リース台帳**（排他の権威）→ **盤**（射影）
- ハートビート + TTL。状態は `active` / `stale` / `expired` / `unknown`
- **鮮度を必ず表示する。**生成物は `valid_until` で自己失効する
- `blocked_on` を明示する（詰まりの理由を推測させない）

### UI

- **同じ API のクライアント。特権経路を作らない**
- 画面は 6 つ（盤 / 状態 / 脳 / 受信箱 / 棋譜 / 蔵）。**モニタリングは作らない**
- **影響シミュレーション**が最大の価値（棋譜のリプレイで「やったらどうなるか」を答える）
- 受信箱は 1 件ずつ。**一括承認は作らない**
- 破壊的操作は必ず「plan / blast radius / 可逆性 / ロールバック経路」を見せる
- ログ・チャットは**プレーンテキストで描画**（XSS → 制御プレーン侵害を防ぐ）
- 全操作に等価な CLI コマンドを併記する

## 保証できること / できないこと

| 到達できる保証 | 対象 |
|---|---|
| ほぼ保証 | 純関数コア（property-based + 状態機械） |
| 検出 | コマンド・権限（MockBukkit）、ブロック挙動（GameTest）、プレイヤー視点（ボット E2E） |
| 検出（相対） | 性能回帰 |
| **保証不能** | **面白さ・コミュニティ・裁定**、絶対性能、描画、バージョン跨ぎ、NMS |

最も危険なのは、保証できていない領域が緑に見えること。
よって **skip を失敗として扱う**のを最優先にする。

## 人間の役割

1. 目標と制約の記述
2. サンプリング監査（`koma brain diff` を読む）
3. 自動で戻せなかった事故の対応
4. コミュニティとの対話

日常はゼロ、例外だけ人間。

## 作る順

1. **skip を失敗にする CI**（テストが嘘をつかないことが前提）
2. ディストリビューション・マニフェスト + ロックファイル + `install --frozen`
3. 薄いシムの骨組み + `decide()` の純関数 + property テスト
4. 不変テーブルの publish / swap
5. クラス索引 + `audit`
6. 盤（リース + `now`）
7. 検出・検証の自動化 → スケジューラ
8. 脳 → UI → ルーター / フリート

**1〜5 はサーバーを一度も起動せずに作れる。**

## 非目標

- Paper のフォーク / Folia / NMS
- 世界状態の並列化（垂直スケール + 複数サーバーで対応）
- 「面白さ」の自動判定
- 監視ダッシュボードの再実装
- 汎用スクリプト言語（表現力より検査可能性）
- 人間が読みやすい設定形式（人間向けは生成された射影）
