# 設計

**この文書の状態**: 設計。実装なし。
この文書と [`glossary.md`](glossary.md)、[`licensing.md`](licensing.md) に出てくる `koma` で始まる名前とスキーマ項目はすべて予定。
分かっていないことは [`unknowns.md`](unknowns.md) に置く。「unknowns #N」はその表の番号。

## 前提

計測していない仮定。

- サーバー運用が属人的だと、再現できず、戻せない
- エージェントに運用を渡すと、確認できない変更が高速に実行される
- 監視だけでは「なぜそうなったか」が残らない
- 承認を増やすとゲートが形骸化する

## 確定事項

| 項目 | 決定 | 理由 |
|---|---|---|
| 土台 | Paper | 可逆性（CoreProtect）と権限（LuckPerms）を既存プラグインで賄える |
| フォーク | しない | 追従コストを年 50–100 日と仮置きしている `[未計測]`（unknowns #3）。マルチスレッド化は Folia が既に扱っている |
| Folia | 使わない | 決定論が失われ、検証コストが増える見込み `[未計測]` |
| NMS | 禁止（静的検査で強制する予定） | バージョン跨ぎで壊れる。コンパイラは検出しない |
| 世界状態の書き手 | 1本 | tick の締切は 50ms（[20 TPS の仕様値](https://minecraft.wiki/w/Tick)）で、複数の書き手の調整をこの時間に収められないと見ている |
| 決定論の適用範囲 | `(seed, version, generatorconfig, datapacks)` の内側のみ | バージョン跨ぎは契約外 |

## 層構成

```
[0] ディストリビューション   Paper（ピン）+ プラグイン束 + datapack + 設定（content-addressed）
[1] 薄いシム                 event → record → enqueue / apply。判断ロジックゼロ
[2] ポリシーエンジン         オフスレッド。不変テーブルを publish（変更時のみ）
[3] 状態                     MariaDB（プラグイン）/ Postgres（制御プレーン）
[4] reconciler               git（望ましい状態）→ plan / apply
[5] 検証                     純関数 / MockBukkit / GameTest / ボットE2E / 負荷
[6] 監査                     決定ログ（リプレイ可能）/ spark
[7] エージェント実行          Tier0 → Tier1 → 定跡(DAG) → ステートレスフリート
```

[1] に判断ロジックを入れない。判断を tick スレッドの外に置き、純関数として検証するため。

## 中核の判断

| 判断 | 内容 |
|---|---|
| ポリシーは配布する、RPC しない | ホットパスは原子参照と配列参照のみ。重い処理は変更時に逃がす |
| 認可カーネルは委譲する | `decide(principal, action, resource, ctx)`。権限は LuckPerms、証跡は CoreProtect |
| 単一書き手 + 不変スナップショット | tick スレッドは読み取りと適用だけを行う |
| state file を持たない | 実状態を毎回読む。真実を 2 つ作らない |
| 可逆性が自律性の上限 | 可逆 = 自動。不可逆と、[自動化しない条件](#サプライチェーン)に当たる更新は人間のゲート |
| 承認ではなく拒否権 | ゲート対象以外はデフォルト実行し、人間は異常だけ revert する。失敗したら前の状態に戻す |
| 推測させず、失敗させる | 曖昧さは解決せずエラーにする |

### state file を持たない理由

state file は「宣言と実物の対応表」で、更新が漏れると実物と食い違う。
サーバーの状態は「ファイル + RCON + プラグインのレジストリ + ロックファイル」で列挙できると見ている（unknowns #15）ので、
対応表を持たずに毎回読む。

### 単位は CRUD ではなくワークフロー

```text
プラグイン更新 = 監査 → plan → 適用 → カナリア → soak → 全台 → 検証
```

カナリアより先に全台へ適用できないので、単体の更新操作に分解できない。単位は skill + 定跡（DAG）にする。

### 反証条件

上の判断が間違っていたと分かる条件。

| 判断 | これが観測されたら間違い |
|---|---|
| 土台は Paper | 定跡の実行中に、CoreProtect で戻せない変更か LuckPerms で表せない権限が発生する |
| フォークしない | Paper API では実装できない機能が定跡に現れ、unknowns #3 の実測値を見た人間が追従を許容する |
| Folia を使わない | Folia でも検証に使える決定論が保てる、または Paper でも得られない |
| NMS 禁止 | Paper API では実装できず、NMS でのみ実装できる機能が定跡に現れる |
| 世界状態の書き手は 1 本 | オフスレッド化した後も tick コストの p99 が 50ms を超える（unknowns #1） |
| 決定論の適用範囲 | 同じ `(seed, version, generatorconfig, datapacks)` で結果が異なる |
| ポリシーは配布する | 原子参照と配列参照では表せない判定が必要になる |
| 認可カーネルは委譲する | LuckPerms と CoreProtect では表せない認可や証跡が必要になる |
| state file を持たない | 実状態の列挙が reconcile の周期に収まらない、または手で加えた変更を列挙で検出できない |
| シムは判断を持たない | オフスレッドの往復待ちが tick に現れる（平均ではなく p99 で） |
| 可逆性が自律性の上限 | 可逆な変更でも事故が起き、戻す判断自体に人間が要る |
| 承認ではなく拒否権 | 人間が気づく前に、戻せない被害が出る |
| 推測させず、失敗させる | 曖昧さによる失敗が多く、定跡が完了しなくなる |
| 定跡は静的 DAG | 静的 DAG で表せない作業が過半になる |
| フリートは会話しない | 成果物経由の受け渡しで情報が落ち、タスクが完了しない |

## サブシステム

### 成果物ストア（蔵）

- content-addressed
- `koma-lock.json` に `provides`（コマンド・権限）と `shaded`（同梱ライブラリ）と
  `license` / `redistributable`（配布可否）を持つ
- ロールバックはポインタ交換。交換自体は数 ms `[未計測]`。再起動が要るものはそのダウンタイムが加わる
  （[分類](#更新のゼロダウンタイム分類)）
- 取れないもの: 依存解決・隔離（Paper に概念が無い）。代わりに静的解析で衝突を検出して失敗させる

### リポジトリに入れないもの

Paper の jar もソースもコミットしない。ロックファイルはハッシュであって中身ではない。

| 対象 | 置き場所 |
|---|---|
| Paper の jar | ストア（インストール時に取得） |
| Paper のソース | 取得しない。改変しないので不要 |
| `paper-api` | 依存宣言のみ（`compileOnly`。jar に同梱しない） |
| Paper の既定設定（コメント付き） | 実行時に生成する |
| ストア本体 | デプロイ環境 |
| 自前プラグイン、上書き設定値、ロックファイル | リポジトリ |

NMS を触らないので `paperweight`（decompile / remap / patch）も要らない。

ストアは DB と同じ扱いでバックアップする。上流から版が消えると、ロックファイルがあっても復元できない。

### 監査（`koma audit`）

- コマンド衝突 / 権限衝突 / 重複 shade / 欠落依存 / 幽霊依存
- shade されたライブラリの CVE（OSV / NVD）
- 能力差分（新権限、新通信先、新依存）
- クラス索引があれば `koma why <class>` で jar の衝突を調べられる。索引を作ってよいかは unknowns #12 次第

### サプライチェーン

```text
①検出 → ②検証 → ③ピン → ④配布
```

- 成果物の取得はストアだけを経由する。ゲームサーバーの外向き通信は絞る方針で、どこまで止められるかは未確定（unknowns #14）
- ハッシュは別経路から取得し、複数ソースの一致を要求する
- ハッシュと署名では防げないもの: 作者アカウント乗っ取り、正当な更新への混入。
  対策の候補はバイトコード差分 + サンドボックス観測 + 段階配布。効果は未確認で（unknowns #8）、サンドボックス化は未着手
- 自動化しない条件: 新権限 / 新通信先 / 新依存 / exec・反射 / 配布チャネルが release 以外。
  これらに当たる更新は人間のゲートを通す
- `review.status != approved` のものは導入不可

### 更新のゼロダウンタイム分類

| クラス | ダウンタイム | 手段 |
|---|---|---|
| 設定 / ポリシー / 権限 / datapack | ゼロ | 再読込 / publish-swap |
| ワールド | ゼロ可（未確認。unknowns #9） | blue/green |
| 自前プラグイン | ゼロ可（未確認。unknowns #4） | シェル + 子クラスローダを最初から設計に入れる |
| 外部プラグイン | ローリング | プロキシ + 複数台 |
| 単一共有ワールドの外部プラグイン | 5–15 秒 `[未計測]`（unknowns #2） | 計画停止。1 つのワールドを共有するのでローリングできない |

スケジュール: 窓 + カナリア + soak + レート制限 + 自動ロールバック条件の事前定義。待っている更新は 1 つにまとめる。

### 形式

- 厳格 JSON（ソート済み、`null` 禁止、整数のみ、ID は文字列、列挙は文字列、
  時刻は ISO-8601 UTC、ハッシュは自己記述、コメント禁止、`additionalProperties: false`、
  重複キーはエラー）
- 文書は JSON、ストリームは JSONL
- `koma describe --json` は全体の状態を 1 ドキュメントで返す。全値に来歴を付ける
- `koma apply --expect-rev` は古い前提を拒否する（TOCTOU を防ぐ）
- クエリは `jq`（読み取り専用。書き戻し禁止）

### スキル

- 成果物として版管理する（プラグインと同じサプライチェーン）
- frontmatter に可逆性クラスと停止条件を持つ。能力はスキルではなくポリシーから与える
- 全ステップに verify コマンドを持たせる
- CLI に対して型検査する（`koma skills verify`）。スキルのエバルも回す
- ログ・チャット・jar 内文字列はデータであって指示ではない

### ルーターとフリート

- Tier0: 毎イベントのトリアージ。tick 経路に入れない。候補は TypeSafe AI の [Jev](https://typesafe.ai/)（未評価。unknowns #13）
- Tier1（Haiku）: 定跡の選択 + パラメータ抽出。閉集合で、`unknown` が第一級
- 分解は静的 DAG。実行時に LLM に分解させない
- `unknown` になった依頼から定跡を書く。`unknown` の割合が定跡の網羅度の指標になる
- フリートはステートレスなワーカーで構成し、成果物だけを受け渡す。会話履歴を渡さない
- ディスパッチャ: タスクリース / 資源リース / 冪等キー / blast radius 上限 / 予算（設計は未着手） / DLQ
- モデルは版 ID で固定し、`jev-latest` のような別名を使わない。版の変更はサプライチェーン事象として扱う

### 脳

事実と信念の定義は[用語集](glossary.md#状態)。

- 脳は再構築可能でなければならない。事実と食い違ったら事実を正とする
- 人間の拒否履歴を方針の候補にする

### 盤

- 棋譜 → リース台帳（排他の権威）→ 盤（射影）
- ハートビート + TTL。状態は `active` / `stale` / `expired` / `unknown`
- 鮮度を必ず表示する。生成物は `valid_until` で自己失効する
- `blocked_on` を明示する（詰まりの理由を推測させない）

### UI

- 同じ API のクライアント。特権経路を作らない
- 画面は盤 / 状態 / 脳 / 受信箱 / 棋譜 / 蔵
- 影響シミュレーション: 棋譜のリプレイで「やったらどうなるか」を答える。答えられるかは未確認（unknowns #16）
- 受信箱は 1 件ずつ。一括承認は作らない
- 破壊的操作は必ず「plan / blast radius / 可逆性 / ロールバック経路」を見せる
- ログ・チャットはプレーンテキストで描画（XSS → 制御プレーン侵害を防ぐ）
- 全操作に等価な CLI コマンドを併記する

## 保証できないこと

保証レベルの定義は[用語集](glossary.md#保証レベル)。
どのレベルでも保証できないもの: 面白さ・コミュニティ・裁定、絶対性能、描画、バージョン跨ぎ、NMS。

テストが skip されたまま CI が緑になると、未検証の領域が検証済みに見える。よって skip を失敗として扱う。

## 人間の役割

1. 目標と制約の記述
2. 週次のサンプリング監査（`koma brain diff` を読む）

4. 自動で戻せなかった事故の対応
5. コミュニティとの対話

## 作る順

1. skip を失敗にする CI
2. ディストリビューション・マニフェスト + ロックファイル + `install --frozen`
3. 薄いシムの骨組み + `decide()` の純関数 + property テスト

7. 検出・検証の自動化 → スケジューラ
8. 脳 → UI → ルーター / フリート

## 非目標

- 世界状態の並列化（垂直スケール + 複数サーバーで対応）
- 「面白さ」の自動判定
- 監視ダッシュボードの再実装
- 汎用スクリプト言語（表現力より検査可能性）
- 人間が読みやすい設定形式（人間向けは生成された射影）
