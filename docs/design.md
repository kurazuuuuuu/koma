# 設計

**この文書の状態**: 設計。実装なし。
この文書と [`glossary.md`](glossary.md)、[`licensing.md`](licensing.md) に出てくる `koma` で始まる名前とスキーマ項目はすべて予定。
分かっていないことは [`unknowns.md`](unknowns.md) に置く。「unknowns #N」はその表の番号。

## 前提

計測していない仮定。

- サーバー運用が属人的だと、再現できず、戻せない
- エージェントに運用を渡すと、確認できない変更が高速に実行される
- 監視だけでは「なぜそうなったか」が残らない
- 承認を増やすとゲートが形骸化する

## 提供形態

セルフホスト。V1 の動作目標は macOS / Linux で、クラウド対応は考えない。

koma 本体のインストールはこの順に進む。

```text
curl でスクリプトを実行 → インストーラー起動 → 依存の確認 → 不足分のインストールを y/n で確認
→ koma のインストール → 最終確認 → オンボーディング
```

オンボーディングは後から再実行できる。API 呼び出しなどに必要な環境変数はオンボーディングで登録する。

ローカルのアクセス先には `localhost` ではなくホスト名を使う。名前はすべて予定で、解決方法は unknowns #20。

- koma 本体: `koma.local`
- Minecraft サーバー: `[alias].mc.koma.local`。ローカルマシンから接続を確認するときに使う。`[alias]` はサーバーごとの別名で、振り分けは unknowns #21

`xxx.orb.local` は OrbStack 固有なので使わない。

### サーバー本体のコンテナ

Minecraft サーバー本体は Docker で動かす。Docker はインストーラーが確認する依存の 1 つになる。

```text
image（digest で固定）  : JRE + OS
読み取り専用マウント     : 蔵の Paper jar、プラグイン束
書き込み可能な volume    : ワールド、実行時の設定
```

- 第三者プラグインを、マシン上の CLI のサインイン情報と環境変数から隔離するために使う。
  これだけでは任意コード実行のサンドボックスにならない（unknowns の「未着手の設計」）
- コンテナは非 root で動かす
- macOS は Docker Desktop と [OrbStack](https://docs.orbstack.dev/docker/) に対応する
- Paper や Velocity を含む image は配らない（unknowns #11）
- [Docker デーモンを操作できるのは信頼できるユーザーだけ](https://docs.docker.com/engine/security/)にする。
  操作するのは koma 本体で、作業エージェントにはデーモンへのアクセスを渡さない。同じマシンで動く CLI からどう止めるかは未確定（unknowns #25）

### ノード

ノードの定義は[用語集](glossary.md#配置)。V1 のノードは koma 本体と同じマシンの `koma-primary` だけで、別ホストのノードは V2 以降に追加する。
追加できるように、V1 でも次を守る。

- 全サーバーが所属ノードを持つ
- 本体は Docker を直接呼ばず、ノードのインターフェースを通す
- 実状態はノード単位で読む
- 成果物はハッシュで指定する

### 入口

プレイヤーの接続は gateway の 1 箇所で受け、ゲームサーバーのポートは公開しない。
外部に公開するときは、TCP をそのまま転送できるサービスを gateway のポートに向ける。特定のサービスに依存しない。
[Cloudflare Tunnel は接続する側にも `cloudflared` が要る](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/protocols/)ので使えない。

- 名前の対応表を 1 つ持ち、`[alias].mc.koma.local` と公開用のホスト名を同じサーバーに割り当てる。Velocity の [forced-hosts](https://docs.papermc.io/velocity/configuration/) はこの表から生成する
- PROXY protocol の受信を設定で有効にできるようにする。転送サービスを挟んでもプレイヤーの実 IP を保つため。有効にすると gateway に届く相手が実 IP を詐称できるので、受け付ける送信元を限定する。Velocity の [`haproxy-protocol`](https://docs.papermc.io/velocity/configuration/) は有効 / 無効だけなので、限定は Velocity の外で行う（unknowns #23）
- UI / API は既定でそのマシンの外（同じ LAN を含む）に出さない。作業エージェントを動かせる入口なのに、認証の設計がない（unknowns の「未着手の設計」）。Minecraft とはポートを分け、転送サービスにはゲーム用だけを渡す
- オンボーディングで転送サービスを使うか y/n で確認する。トークンは環境変数に登録し、再実行で後から追加できる
- [Mojang 認証は Velocity が行う](https://docs.papermc.io/velocity/player-information-forwarding/)ので、ゲームサーバーの `online-mode` を切り、modern forwarding の secret を設定する。gateway 以外からゲームサーバーに接続できないように隔離する

## 確定事項

| 項目 | 決定 | 理由 |
|---|---|---|
| 土台 | Paper | 可逆性（CoreProtect）と権限（LuckPerms）を既存プラグインで賄える |
| フォーク | しない | 追従コストを年 50–100 日と仮置きしている `[未計測]`（unknowns #3）。マルチスレッド化は Folia が既に扱っている |
| Folia | 使わない | 決定論が失われ、検証コストが増える見込み `[未計測]` |
| NMS | 禁止（静的検査で強制する予定） | バージョン跨ぎで壊れる。コンパイラは検出しない |
| 世界状態の書き手 | 1本 | tick の締切は 50ms（[20 TPS の仕様値](https://minecraft.wiki/w/Tick)）で、複数の書き手の調整をこの時間に収められないと見ている |
| 決定論の適用範囲 | `(seed, version, generatorconfig, datapacks)` の内側のみ | バージョン跨ぎは契約外 |
| 本体の言語 | Rust（stable、Cargo） | 閉集合を `enum` と網羅的な `match` で、全域必須と未知のキーの拒否を serde で強制できる（[形式](#形式)）。ワークスペース分割と debug 情報の削減で、アプリ側の変更後の `cargo check` は 0.19 s、共有型の変更後の `cargo build` は 7.54 s `[計測: Apple M4 10コア 16GB, rustc 1.99.0, 合成コード（構造体 300 個、依存 255 クレート）, 2026-11-06]` |
| プラグインの言語 | Java 25（Gradle Kotlin DSL） | [Paper の開発手順](https://docs.papermc.io/paper/dev/project-setup/)が Java 25 と Gradle Kotlin DSL を前提にしている |
| V1 の範囲 | 1 つの koma で 1 コミュニティ | コミュニティ間の分離を設計せずに済み、検証の範囲を 1 コミュニティに絞れる |
| ノード | 形式を最初から入れ、別ホストは V2 以降（[ノード](#ノード)） | 後から本体と Docker の間に境界を入れると、Docker を呼ぶ箇所をすべて直すことになる |
| gateway | Velocity（`koma-primary` 上の 1 段） | ゲームサーバーの外向き通信をなくせる可能性がある（unknowns #14） |

## 層構成

```
[0] ディストリビューション   Paper（ピン）+ プラグイン束 + datapack + 設定（content-addressed）
[1] 薄いシム                 event → record → enqueue / apply。判断ロジックゼロ
[2] ポリシーエンジン         オフスレッド。不変テーブルを publish（変更時のみ）
[3] 状態                     MariaDB（プラグイン）/ Postgres（制御プレーン）
[4] reconciler               git（望ましい状態）→ plan / apply
[5] 検証                     純関数 / MockBukkit / GameTest / ボットE2E / 負荷
[6] 監査                     決定ログ（リプレイ可能）/ spark
[7] エージェント実行          Tier0 → Tier1 → 定跡(DAG) → ステートレスフリート
```

[1] に判断ロジックを入れない。判断を tick スレッドの外に置き、純関数として検証するため。

## 中核の判断

| 判断 | 内容 |
|---|---|
| ポリシーは配布する、RPC しない | ホットパスは原子参照と配列参照のみ。重い処理は変更時に逃がす |
| 認可カーネルは委譲する | `decide(principal, action, resource, ctx)`。権限は LuckPerms、証跡は CoreProtect |
| 単一書き手 + 不変スナップショット | tick スレッドは読み取りと適用だけを行う |
| state file を持たない | 実状態を毎回読む。真実を 2 つ作らない |
| 可逆性が自律性の上限 | 可逆 = 自動。不可逆と、[自動化しない条件](#サプライチェーン)に当たる更新は人間のゲート |
| 承認ではなく拒否権 | ゲート対象以外はデフォルト実行し、人間は異常だけ revert する。失敗したら前の状態に戻す |
| 推測させず、失敗させる | 曖昧さは解決せずエラーにする |

### state file を持たない理由

state file は「宣言と実物の対応表」で、更新が漏れると実物と食い違う。
サーバーの状態は「ファイル + RCON + プラグインのレジストリ + ロックファイル」で列挙できると見ている（unknowns #15）ので、
対応表を持たずに毎回読む。

### 単位は CRUD ではなくワークフロー

```text
プラグイン更新 = 監査 → plan → 適用 → カナリア → soak → 全台 → 検証
```

カナリアより先に全台へ適用できないので、単体の更新操作に分解できない。単位は skill + 定跡（DAG）にする。

### 反証条件

上の判断が間違っていたと分かる条件。

| 判断 | これが観測されたら間違い |
|---|---|
| セルフホスト（V1 はクラウド非対応） | 想定する利用者が macOS / Linux のマシンを用意できず、クラウドなしでは導入できない |
| 作業エージェントは既定でマシンの CLI | CLI の版・権限を koma のポリシーで制限できない、または規約上自動運用に使えない |
| サーバー本体は Docker | 同じプラグイン構成で、コンテナ内の tick 時間の p99 が直接起動より悪化して 50ms を超える（unknowns #19）、コンテナ内のプラグインからマシンのサインイン情報を読める、または作業エージェントが Docker デーモンを操作できる（unknowns #25） |
| ローカルのアクセス先にホスト名を使う | 対応する環境で名前解決に追加設定が要り、導入の失敗原因になる（unknowns #20） |
| V1 は 1 つの koma で 1 コミュニティ | 想定する利用者の多くが、1 つの koma で複数のコミュニティを運用する必要がある |
| ノード形式を最初から入れる | 別ホストのノードを足すときにインターフェースを作り直す、または V2 以降も別ホストのノードが使われない |
| gateway は Velocity 1 段 | forced-hosts で `[alias]` を振り分けられない（unknowns #21）、転送サービスの PROXY protocol を受けられないか受け付ける送信元を限定できない（unknowns #23）、または Mojang 認証を任せてもゲームサーバーの外向き通信が減らない（unknowns #14） |
| UI / API を既定で外に出さない | 想定する利用者の多くが別のマシンから操作する必要があり、既定のままでは koma を使えない |
| 土台は Paper | 定跡の実行中に、CoreProtect で戻せない変更か LuckPerms で表せない権限が発生する |
| フォークしない | Paper API では実装できない機能が定跡に現れ、unknowns #3 の実測値を見た人間が追従を許容する |
| Folia を使わない | Folia でも検証に使える決定論が保てる、または Paper でも得られない |
| NMS 禁止 | Paper API では実装できず、NMS でのみ実装できる機能が定跡に現れる |
| 世界状態の書き手は 1 本 | オフスレッド化した後も tick コストの p99 が 50ms を超える（unknowns #1） |
| 決定論の適用範囲 | 同じ `(seed, version, generatorconfig, datapacks)` で結果が異なる |
| 本体は Rust | 実装が進んだ分割後の構成で、アプリ側の変更後の `cargo check` が 5 秒（仮の基準）を超え続ける、必要な Docker API が [bollard](https://github.com/fussybeaver/bollard) にも `docker` CLI にもない、またはエージェントの実装がコンパイルエラーの修正で完了しなくなる |
| プラグインは Java | 定跡に必要な機能が、Java から Paper API と MockBukkit を使って実現できない |
| ポリシーは配布する | 原子参照と配列参照では表せない判定が必要になる |
| 認可カーネルは委譲する | LuckPerms と CoreProtect では表せない認可や証跡が必要になる |
| state file を持たない | 実状態の列挙が reconcile の周期に収まらない、または手で加えた変更を列挙で検出できない |
| シムは判断を持たない | オフスレッドの往復待ちが tick に現れる（平均ではなく p99 で） |
| 可逆性が自律性の上限 | 可逆な変更でも事故が起き、戻す判断自体に人間が要る |
| プレイヤーの進行が消える戻し方は `irreversible` | 事故対応でワールドの巻き戻しが必要になり、人間のゲートを待つ間に被害が広がる |
| 承認ではなく拒否権 | 人間が気づく前に、戻せない被害が出る |
| 推測させず、失敗させる | 曖昧さによる失敗が多く、定跡が完了しなくなる |
| 定跡は静的 DAG | 静的 DAG で表せない作業が過半になる |
| フリートは会話しない | 成果物経由の受け渡しで情報が落ち、タスクが完了しない |
| 作業エージェントは検査、ゲート、予算の設定を変更できない | 検査の修正が人間待ちで滞り、タスクの多くが止まったままになる |
| 受け入れテストと実装の役を分ける | 分けても、受け入れテストが見逃す欠陥の割合が変わらない |
| 書く役とレビューする役を分ける | 別の役のレビューが、機械的な検査を超える欠陥を見つけない |
| 同じベンダーの別セッションのレビューを認める | 別ベンダーなら検出できる欠陥を繰り返し見逃す（unknowns #22） |
| 待ちのタスクがなければ止まる | 止まっている間に検出できたはずの劣化が放置され、プレイヤーに影響が出る |
| 失敗が続いたタスクは止めて次へ進む | 止めたタスクの多くが、続けていれば完了していた |
| 全体をすぐ止める | 止めると定跡が戻せない途中状態で残る |

## サブシステム

### 成果物ストア（蔵）

- content-addressed
- `koma-lock.json` に `provides`（コマンド・権限）と `shaded`（同梱ライブラリ）と
  `license` / `redistributable`（配布可否）を持つ
- ロールバックはポインタ交換。交換自体は数 ms `[未計測]`。再起動が要るものはそのダウンタイムが加わる
  （[分類](#更新のゼロダウンタイム分類)）
- 取れないもの: 依存解決・隔離（Paper に概念が無い）。代わりに静的解析で衝突を検出して失敗させる

### リポジトリに入れないもの

Paper の jar もソースもコミットしない。ロックファイルはハッシュであって中身ではない。

| 対象 | 置き場所 |
|---|---|
| Paper と Velocity の jar | ストア（インストール時に取得） |
| Paper のソース | 取得しない。改変しないので不要 |
| `paper-api` | 依存宣言のみ（`compileOnly`。jar に同梱しない） |
| Paper の既定設定（コメント付き） | 実行時に生成する |
| ストア本体 | デプロイ環境 |
| 自前プラグイン、上書き設定値、ロックファイル | リポジトリ |

NMS を触らないので `paperweight`（decompile / remap / patch）も要らない。

ストアは DB と同じ扱いでバックアップする。上流から版が消えると、ロックファイルがあっても復元できない。

### 監査（`koma audit`）

- コマンド衝突 / 権限衝突 / 重複 shade / 欠落依存 / 幽霊依存
- shade されたライブラリの CVE（OSV / NVD）
- 能力差分（新権限、新通信先、新依存）
- クラス索引があれば `koma why <class>` で jar の衝突を調べられる。索引を作ってよいかは unknowns #12 次第

### サプライチェーン

```text
①検出 → ②検証 → ③ピン → ④配布
```

- 成果物の取得はストアだけを経由する。ゲームサーバーの外向き通信は絞る方針で、どこまで止められるかは未確定（unknowns #14）
- ハッシュは別経路から取得し、複数ソースの一致を要求する
- ハッシュと署名では防げないもの: 作者アカウント乗っ取り、正当な更新への混入。
  対策の候補はバイトコード差分 + サンドボックス観測 + 段階配布。効果は未確認で（unknowns #8）、サンドボックス化は未着手
- 自動化しない条件: 新権限 / 新通信先 / 新依存 / exec・反射 / 配布チャネルが release 以外。
  これらに当たる更新は人間のゲートを通す
- `review.status != approved` のものは導入不可

### 更新のゼロダウンタイム分類

| クラス | ダウンタイム | 手段 |
|---|---|---|
| 設定 / ポリシー / 権限 / datapack | ゼロ | 再読込 / publish-swap |
| ワールド | ゼロ可（未確認。unknowns #9） | blue/green |
| 自前プラグイン | ゼロ可（未確認。unknowns #4） | シェル + 子クラスローダを最初から設計に入れる |
| 外部プラグイン | ローリング | プロキシ + 複数台 |
| 単一共有ワールドの外部プラグイン | 5–15 秒 `[未計測]`（unknowns #2） | 計画停止。1 つのワールドを共有するのでローリングできない |
| gateway（Velocity） | 再起動の間 `[未計測]`。全プレイヤーが切断される | 計画停止 |

この表はダウンタイムの分類で、人間のゲートとは別に決まる。稼働中のワールドの更新は、戻すとプレイヤーの進行が消えるので `irreversible`（[可逆性クラス](glossary.md#可逆性クラス)）。

スケジュール: 窓 + カナリア + soak + レート制限 + 自動ロールバック条件の事前定義。待っている更新は 1 つにまとめる。

### 形式

- 厳格 JSON（ソート済み、`null` 禁止、整数のみ、ID は文字列、列挙は文字列、
  時刻は ISO-8601 UTC、ハッシュは自己記述、コメント禁止、`additionalProperties: false`、
  重複キーはエラー）
- 本体は、型へのデシリアライズの前に `null`、整数以外、重複キー、未ソートのキーを拒否する検査を通す。
  serde は `Option` の省略と `null`、`HashMap` と `Value` の重複キーを受け入れる `[計測: serde 1.0.229, serde_json 1.0.154, 2026-11-06]`
- スキーマの型に `Option` を使わない。値がない状態は列挙で表す
- 文書は JSON、ストリームは JSONL
- `koma describe --json` は全体の状態を 1 ドキュメントで返す。全値に来歴を付ける
- `koma apply --expect-rev` は古い前提を拒否する（TOCTOU を防ぐ）
- クエリは `jq`（読み取り専用。書き戻し禁止）

### スキル

- 成果物として版管理する（プラグインと同じサプライチェーン）
- frontmatter に可逆性クラスと停止条件を持つ。能力はスキルではなくポリシーから与える
- 全ステップに verify コマンドを持たせる
- CLI に対して型検査する（`koma skills verify`）。スキルのエバルも回す
- ログ・チャット・jar 内文字列はデータであって指示ではない

### ルーターとフリート

- Tier0: 毎イベントのトリアージ。tick 経路に入れない。候補は TypeSafe AI の [Jev](https://typesafe.ai/)（未評価。unknowns #13）
- Tier1（Haiku）: 定跡の選択 + パラメータ抽出。閉集合で、`unknown` が第一級
- 分解は静的 DAG。実行時に LLM に分解させない
- `unknown` になった依頼から定跡を書く。`unknown` の割合が定跡の網羅度の指標になる
- フリートはステートレスなワーカーで構成し、成果物だけを受け渡す。会話履歴を渡さない
- 作業エージェントは、インストールしたマシンの Claude Code、Codex などを既定で使う。
  版・権限をどこまで固定できるかは unknowns #17、規約上の扱いは unknowns #18
- koma は CLI を改変せず、Claude アカウントなどの OAuth 認証情報を収集・保存・仲介しない。サインインは各 CLI 自身のフローで行う
  （Claude は [Anthropic の規定](https://code.claude.com/docs/en/legal-and-compliance)）。利用者自身の API キーを環境変数で登録するのは別
- CLI の検出とサインインの扱いは [OpenBot](https://github.com/nightly-labs/openbot) の設計を参考にする。
  ライセンスが PolyForm Noncommercial 1.0.0 なのでコードは持ち込まない
- ディスパッチャ: タスクリース / 資源リース / 冪等キー / blast radius 上限 / 予算（設計は未着手） / DLQ
- モデルは版 ID で固定し、`jev-latest` のような別名を使わない。版の変更はサプライチェーン事象として扱う

### 脳

事実と信念の定義は[用語集](glossary.md#状態)。

- 脳は再構築可能でなければならない。事実と食い違ったら事実を正とする
- 人間の拒否履歴を方針の候補にする

### 盤

- 棋譜 → リース台帳（排他の権威）→ 盤（射影）
- ハートビート + TTL。状態は `active` / `stale` / `expired` / `unknown`
- 鮮度を必ず表示する。生成物は `valid_until` で自己失効する
- `blocked_on` を明示する（詰まりの理由を推測させない）

### UI

- 同じ API のクライアント。特権経路を作らない
- 画面は盤 / 状態 / 脳 / 受信箱 / 棋譜 / 蔵
- 影響シミュレーション: 棋譜のリプレイで「やったらどうなるか」を答える。答えられるかは未確認（unknowns #16）
- 受信箱は 1 件ずつ。一括承認は作らない
- 破壊的操作は必ず「plan / blast radius / 可逆性 / ロールバック経路」を見せる
- ログ・チャットはプレーンテキストで描画（XSS → 制御プレーン侵害を防ぐ）
- 全操作に等価な CLI コマンドを併記する

## 保証できないこと

保証レベルの定義は[用語集](glossary.md#保証レベル)。
どのレベルでも保証できないもの: 面白さ・コミュニティ・裁定、絶対性能、描画、バージョン跨ぎ、NMS。

テストが skip されたまま CI が緑になると、未検証の領域が検証済みに見える。よって skip を失敗として扱う。

## 自律の規則

作業エージェントを人間なしで動かすときの規則。[中核の判断](#中核の判断)と[自動化しない条件](#サプライチェーン)に次を足す。koma 自身の開発にも同じ規則を使う。

1. 作業エージェントは検査、ゲート、予算の設定を変更できない
2. 受け入れテストを書く役と実装役を分ける。実装役は受け入れテストを変更できない
3. 書いた役とレビューする役を分ける。マシンの CLI が 1 つなら、同じベンダーの別セッションを認める（十分かは unknowns #22）
4. 待ちのタスクがなければ止まる。タスクを発明しない。定期の検出はスケジューラがタスクとして入れる
5. 予算の上限を持ち、失敗が続いたタスクは `blocked_on` に理由を残して止め、次へ進む。上限と回数は未定（unknowns の「未着手の設計」）
6. 全体をすぐ止める手段を持つ

## 人間の役割

1. 目標と制約の記述
2. 週次のサンプリング監査（`koma brain diff` を読む）
3. 人間のゲートに来た項目の判断（受信箱）
4. 自動で戻せなかった事故の対応
5. コミュニティとの対話

## 作る順

1. skip を失敗にする CI
2. ディストリビューション・マニフェスト + ロックファイル + `install --frozen`
3. インストーラー + ノードのインターフェース
4. 薄いシムの骨組み + `decide()` の純関数 + property テスト
5. 不変テーブルの publish / swap
6. `audit`。クラス索引は unknowns #12 が解けてから
7. 盤（リース + `now`）
8. 検出・検証の自動化 → スケジューラ
9. 脳 → UI → ルーター / フリート

1〜6 はサーバーを起動せずに作れる想定（未検証）。

## 非目標

- 世界状態の並列化（垂直スケール + 複数サーバーで対応）
- 1 つの koma での複数コミュニティの分離（マルチテナント）
- 「面白さ」の自動判定
- 監視ダッシュボードの再実装
- 汎用スクリプト言語（表現力より検査可能性）
- 人間が読みやすい設定形式（人間向けは生成された射影）
